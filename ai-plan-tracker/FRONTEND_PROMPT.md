## 提示词正文

你是一名擅长信息设计的前端工程师。请为「AI 套餐追踪」网站设计并实现前端界面。

**核心风格要求：信息清楚明了。** 用户打开任何一页，3 秒内要能回答一个具体问题（「哪个最便宜？」「最近改了什么？」「我是不是买重了？」）。界面为信息服务，不为装饰服务。

### 一、产品背景

一个中文网站，帮普通用户看清各家 AI 订阅套餐和 API 的价格，追踪套餐规则变更，检查自己的订阅是否重叠。

- 技术栈：Next.js 16（App Router，静态导出）、React 19、TypeScript。不引入 UI 组件库，样式用纯 CSS + CSS 变量。
- 语言：全站简体中文；价格统一以美元展示，人民币标价的档位同时显示原价（如「¥99/月」）并注明按汇率估算。
- 数据全部是本地静态数据（`src/data/*.ts`），无后端；「我的订阅」存 localStorage。

### 二、数据结构（设计时必须覆盖所有字段）

```ts
type Capability = "chat" | "reasoning" | "coding-ide" | "coding-cli"
                | "research" | "image" | "video" | "search";
// 中文名：对话 / 推理 / IDE 编程 / 命令行编程 / 深度研究 / 图像 / 视频 / 搜索

type Verification = "official" | "secondary"; // 已核对官方 / 待核实

interface Plan {          // 订阅档位，约 30 条，12 家厂商
  id; vendor; product; plan;
  monthlyUsd: number;          // 月付价（美元）
  annualMonthlyUsd?: number;   // 年付折合每月
  originalPrice?: string;      // 非美元原价
  capabilities: Capability[];
  usageNote: string;           // 额度一句话说明
  verification; sourceUrl; checkedAt;
}

interface ApiModel {      // 按 token 计费模型，约 25 条
  id; vendor; model;
  inputPer1M: number; cachedInputPer1M?: number; outputPer1M: number; // 美元/百万 token
  note?; verification; sourceUrl; checkedAt;
}

interface Change {        // 变更日志，时间倒序
  id; date;               // YYYY-MM-DD 或 YYYY-MM
  vendor; planIds: string[];
  type: "downgrade" | "upgrade" | "rule-change" | "promo-start"
      | "promo-end" | "price-change" | "new-plan";
  title; before?; after?; // 事实
  note;                   // 编辑解读（必须与事实在视觉上分开）
  verification; sourceUrl;
}
```

### 三、页面与要解决的问题

**全局导航**：顶部固定导航，三个入口「价格一览 / 变更日志 / 我的订阅」，当前页高亮。右侧显示数据核对日期。

**1. `/` 价格一览**（两个标签页：订阅套餐 / API 按 token，`/#api` 直达 API）

- 订阅套餐视图
  - 顶部：四个价位带概览卡（入门 ≤$20 / 进阶 $21–99 / 重度 $100–199 / 旗舰 ≥$200），每张卡显示档位数量和价格区间。
  - 「每类能力最便宜 / 最贵」：8 行对照表，一行一个能力，左列最便宜档位、右列最贵档位，带价格。
  - 完整价格排行：从便宜到贵的表格，列为「厂商·产品·档位 / 月付价 / 年付折合 / 能力标签 / 额度说明 / 核对状态」。
  - 控件：能力筛选（多选标签）、月付 / 年付折合切换、「只看已核对」开关。控件放在表格正上方一行内，改动后结果即时更新并显示「共 N 条」。
- API 视图
  - 按混合单价（输入:输出 = 3:1）分四档：经济 / 标准 / 高级 / 旗舰。
  - 输入价—输出价散点图，双轴对数刻度，点可悬停显示模型名和两个价格。
  - 「订阅还是 API」计算器：输入每月输入 token、输出 token、缓存命中比例 → 输出每个模型的 API 月费，并与同厂商最便宜订阅价对比，明确标出「API 更省」或「订阅更省」及差额。

**2. `/changes/` 变更日志**

- 时间线列表，按月份分组，时间倒序。
- 每条变更卡片结构固定：
  1. 首行：日期 · 厂商 · 变更类型标签（降级用红、升级用绿、规则变更用黄、其余中性色）
  2. 标题（一句话）
  3. **事实区**：「变更前 → 变更后」左右对照（窄屏上下排列）
  4. **解读区**：视觉上明显区分（如左侧竖线 + 浅底 + 「解读」小标签）
  5. 底部：原文出处链接 + 核对状态
- 顶部筛选：按厂商、按类型、「只看影响我的订阅」（读取 localStorage）。

**3. `/mine/` 我的订阅**

- 左侧（窄屏在上）：按厂商分组的档位勾选列表。
- 右侧结果区，从上到下：
  1. 月度合计大数字（月付 / 年付折合两种）
  2. 能力重叠矩阵：行为已选档位，列为 8 类能力，被 2 个及以上档位覆盖的能力列高亮
  3. 「可考虑去掉」建议：每条写明哪个档位、为什么（能力已被谁覆盖）、每月可省多少
- 空状态：没勾选时给出一句引导，而不是空白。
- 明确提示「数据只保存在本浏览器」。

### 四、视觉与信息设计规范

**原则**
1. **数字优先**：价格是主角。价格用等宽数字（`font-variant-numeric: tabular-nums`），右对齐，比周围文字大一号或加粗。
2. **一屏一个问题**：每个区块有一个问句式或结论式小标题（如「$20 以内能买到什么」），而不是「数据概览」这种空泛标题。
3. **层级只有三级**：页面标题 / 区块标题 / 正文。不要多于三种字号层级的正文信息。
4. **颜色只表达含义**：颜色只用于价位带、变更类型、核对状态、图表系列；不用颜色做装饰。任何颜色含义都要配文字或图标，不能只靠颜色区分。
5. **不确定就说出来**：`secondary` 数据一律显示「待核实」徽章（黄色描边小标签），悬停说明含义；所有数据旁可点击查看出处。
6. **少即是多**：不要渐变、玻璃拟态、大插图、装饰性阴影、动画入场。卡片用 1px 细边框区分，不用重阴影。

**色彩（沿用现有 token，定义在 `:root`，暗色模式在 `prefers-color-scheme: dark` 与 `[data-theme="dark"]` 下重定义）**
- 背景 `--page #f9f9f7`、卡片 `--surface #fcfcfb`、次级底 `--surface-2 #f3f2ee`
- 文字 `--ink #0b0b0b`、次要 `--ink-2 #52514e`、弱化 `--muted #898781`
- 强调 `--accent #2a78d6`；正向 `--good-text #006300`；警示 `--warn #fab219`；危险 `--critical #d03b3b`
- 价位带同色相色阶，越贵越深：`--tier-1 #86b6ef` → `--tier-4 #0d366b`
- 图表系列：输入 `--series-in #2a78d6`、输出 `--series-out #eb6834`

**排版**
- 字体：系统字体栈，中文优先 `"PingFang SC", "Microsoft YaHei"`，数字可用 `Inter` / 系统无衬线。
- 正文 15px，行高 1.6；表格 14px；区块标题 18px 600；页面标题 26px 700。
- 内容最大宽度 1120px，居中；区块间距 40px，卡片内边距 16–20px。

**表格**
- 表头吸顶，斑马纹用极浅的 `--surface-2`；行悬停高亮。
- 价格列右对齐；能力用小号胶囊标签，最多一行，溢出显示「+N」。
- 支持点击表头排序，当前排序列显示箭头。

**响应式**
- ≥1024px：多列布局；768–1023px：两列降为单列，表格保留；<768px：表格转为卡片列表（每张卡：档位名 + 大号价格 + 能力标签 + 额度说明），页面左右留白 16px，不允许横向滚动。

**可访问性**
- 文字对比度 ≥ 4.5:1；所有控件可键盘操作并有可见焦点环；图表提供等价的数据表（可折叠）。
